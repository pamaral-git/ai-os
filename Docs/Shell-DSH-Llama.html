OpenShell & DeepSeek Harness Reference

Architectural specification, configuration manual, and operational guide for running sandboxed local coding agents with native Metal acceleration on Apple Silicon.

01 Security Architecture & Boundary Model

Autonomous coding agents inspect unknown code, generate shell commands, and execute tool calls. Running them unsandboxed on macOS exposes developer credentials, SSH keys, private project files, and system shells to prompt injection or model hallucination.

Core Isolation Principles defense-in-depth
  • Host-Accelerated Inference: llama-swap runs natively on macOS to maintain full Apple Silicon unified memory bandwidth (Metal GPU acceleration). Models and weights never run inside a virtual machine.
  • Agent Containment: The agent environment runs strictly inside an unprivileged Linux container (UID/GID 1500) managed by OpenShell in a rootless Podman Machine VM, governed by Landlock filesystem constraints and OPA network policies.
  • Dedicated Sandboxed Port (9008 vs 8080): The primary host llama-swap (port 8080) carries interactive agent macros with --tools all, --ui-mcp-proxy, and MCP servers. The built-in llama.cpp shell tool executes raw sh -c commands on the host Mac. The sandboxed instance on port 9008 uses llama-shell.yaml, which strictly strips all tool capabilities, MCP endpoints, and binds only to 127.0.0.1.

03 DeepSeek Harness: Profiles & Workspaces

DeepSeek Harness provides a browser-based agent workspace that solves the configuration creep of host-installed tools like OMP or Pi, which can accidentally mount host directories or execute unsanctioned plugins. It runs in unprivileged containers with dual operational profiles and dual storage binding options.

DeepSeek Harness Architecture & Dual Boundaries dual-container
  • UI Boundary Container (ui): Establishes a hardened network namespace. Uses temporary NET_ADMIN during bootstrap to install strict iptables drop rules, then permanently drops all capabilities before running the relay as unprivileged UID 10002. Only relay traffic to port 9008 on the host is allowed into llama-swap.
  • Core Engine Container (core): Runs the DSH engine as unprivileged UID 10001, joined directly to the UI container's network namespace (network_mode: service:ui). All host filesystem mounts are blocked unless an explicit drivework bridge is provided.
  • Network Profile 1 — Airgapped (--airgap): Completely blinds the agent. UDP/TCP port 53 (DNS) is rejected, all external IPs are dropped. Egress is strictly limited to localhost loopback and the Mac host port 9008 llama relay.
  • Network Profile 2 — Contained Web (--web): Middle ground for internet research, cloning GitHub repositories, and accessing scientific libraries (Libgen, arXiv). Resolves DNS and allows HTTP/HTTPS (80/443), while strictly dropping private RFC1918 subnets (LANs) and cloud metadata services (169.254.169.254).
  • Workspace Profile 1 — Disposable Tmpfs (--temp): Entire workspace (/workspace) and state live in container RAM. Nothing touches host storage; when stopped, everything vanishes cleanly.
  • Workspace Profile 2 — Permanent Drivework (--permanent / --drivework): Binds to /Volumes/X-Drive/drivework. Synchronized continuously so projects, downloads, and generated files persist across sessions.

Launching DeepSeek Harness with Profiles

Terminal
# 1. Strict airgapped mode with disposable in-memory workspace (Default)
~/Config/Openshell/dsh.sh up --airgap --temp

# 2. Contained web research mode with permanent /Volumes/X-Drive/drivework binding
~/Config/Openshell/dsh.sh up --web --permanent

# 3. Retrieve the browser authentication link anytime
~/Config/Openshell/dsh.sh link

The launcher prints a single-use authentication link:

Output
DeepSeek Harness is Ready!
Open this link in your Mac browser:
http://127.0.0.1:8999/?token=...

04 Universal CLI Project Runner

When you want to run terminal tools (e.g., Python scripts, build tasks, git commands) against local code while maintaining sandbox guarantees, use the run subcommand. It dynamically maps your current working directory (/) into the sandbox.

Terminal
cd /path/to/my-project

# Launch an interactive shell inside the sandbox on this directory
~/Config/llm-shell.sh run /bin/bash

# Or execute a single script or command
~/Config/llm-shell.sh run python3 build.py
Execution Lifecycle sync-cycle
  1. Directory Safety Check: Refuses to run on top-level system directories (/, /Users/..., /Users, /Volumes).
  2. Upload: Copies current directory contents into /sandbox/<project> inside the container.
  3. Execution: Executes the requested binary with --workdir /sandbox/<project> under Landlock and network restrictions.
  4. Download: Downloads changed and created files back to your Mac project directory when the command exits. (Disable with SYNC_BACK=0 for read-only runs).

05 Model Sanitizer Tool (generate-shell-swap.py)

The sanitizer script ingests your primary llama-swap.yaml and transforms it into a safe, fail-closed llama-shell.yaml.

Terminal
# Sanitize all models from main config into llama-shell.yaml
python3 ./Config/create-llama-shell.py

# Or filter to a specific subset of models
python3 ./Config/create-llama-shell.py --models ling,qwen4b,xspark
Sanitizer Enforcements fail-closed
  • Host Flag Elimination: Strips --tools, --ui-mcp-proxy, --mcp-servers-config, and macros across all models.
  • Localhost Binding: Rewrites all --host parameters to 127.0.0.1. Non-loopback addresses cause validation failure.
  • Port Isolation: Sets startPort: 11080 to prevent collisions with the primary llama-swap instances starting at 10001. Automatically sets listening port to match policy (9008).
  • Atomic Verification: Scans generated configuration before writing. If any forbidden token is found or llama-swap -validate fails, the operation halts and leaves the target file untouched.

2. OpenShell Sandbox Policy (~/Config/Openshell/policy.yaml)

policy.yaml
version: 1

            process:
              run_as_user: "1500"
              run_as_group: "1500"

            landlock:
              # best_effort silently skips filesystem rules if the Podman VM kernel lacks Landlock.
              # llama-openshell.sh therefore probes at startup (writes to /var/tmp, which is not listed
              # below) and refuses to start llama-swap if that write succeeds.
              compatibility: best_effort

            filesystem_policy:
              include_workdir: true
              read_only:
                - /usr
                - /lib
                - /lib64
                - /bin
                - /sbin
                - /etc
                - /dev/urandom
                - /proc
              read_write:
                - /tmp
                - /dev/null

            network_policies:
              local_llama_inference:
                endpoints: # 192.168.127.254 is Podman Machine's standard host-gateway address
                  - host: "192.168.127.254"
                    port: 9008
                    protocol: rest
                    enforcement: enforce
                    rules:
                      - allow:
                          method: GET
                          path: "/health"
                      - allow:
                          method: GET
                          path: "/v1/models"
                      - allow:
                          method: POST
                          path: "/v1/chat/completions"
                      - allow:
                          method: POST
                          path: "/v1/completions"
                      - allow:
                          method: POST
                          path: "/v1/embeddings"
                # Anything these binaries run inside the sandbox can send arbitrary prompts to your
                # local models through the allowed routes. Trim this list to what the agent needs.
                binaries:
                  - path: "/usr/bin/curl"
                  - path: "/usr/local/bin/node"
                  - path: "/usr/local/bin/python3"

08 Operations & Troubleshooting

1. Gateway Service Status openshell

If OpenShell reports disconnected or inactive gateway:

Terminal
# Re-register local mTLS gateway
openshell gateway add https://localhost:17670 --local --name openshell 2>&1 || true
openshell gateway select openshell
openshell status
openshell gateway info
2. Podman Machine & Socket Forwarding podman

Ensure the rootless VM is active and the Docker client socket symlink is in place:

Terminal
# Check VM status
podman machine start podman-machine
podman info --format '{{.Host.Security.Rootless}}'  # Must output 'true'

# Ensure Docker CLI socket link points to Podman API socket
mkdir -p ~/.docker/run
ln -sf "/var/folders/.../T/podman/podman-machine-api.sock" ~/.docker/run/docker.sock
3. Port 9008 In Use llama-swap

To inspect or terminate any dangling sandboxed llama-swap process:

Terminal
lsof -nP -iTCP:9008 -sTCP:LISTEN
pkill -f "llama-swap.*9008"
